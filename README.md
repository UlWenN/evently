# Evently — афиша мероприятий

Evently — клиентское одностраничное веб-приложение для просмотра и поиска городских мероприятий: концертов, кинопоказов, выставок, лекций, фестивалей и театральных постановок. Проект создан в рамках лабораторных работ по веб-программированию: в лабораторной работе № 1 была подготовлена HTML/CSS-страница, а в лабораторной работе № 2 добавлена интерактивная логика на JavaScript.

## Для кого этот проект

Для жителей города, которые хотят найти мероприятие по месту проведения, городу, категории или дате, а также предложить собственное событие.

## Возможности приложения

- **Каталог мероприятий.** При первом запуске отображаются шесть демонстрационных мероприятий. Карточки создаются динамически с помощью JavaScript.
- **Поиск по тексту.** Иконка поиска открывает модальное окно. Результаты обновляются по мере ввода; поиск не зависит от регистра и учитывает название, город, место проведения, категорию и описание мероприятия. Из результата можно выбрать отдельное событие или перейти к фильтрации по его категории.
- **Фильтрация.** Основная форма позволяет отбирать события по месту проведения или городу, категории и дате. Пункт «Все категории» сбрасывает фильтр категории.
- **Сортировка.** События можно упорядочить по дате по возрастанию или убыванию.
- **Предложение мероприятия.** В модальном окне пользователь заполняет название, дату, место, город, категорию и описание. Перед отправкой выполняется клиентская проверка полей.
- **Модерация.** Предложенные мероприятия попадают в отдельный список ожидания. В демонстрационном режиме модератора их можно одобрить или отклонить.
- **Удаление мероприятий.** При включённом режиме модератора у карточек опубликованных мероприятий появляется кнопка «Удалить».
- **Сохранение данных.** Каталог и список предложений сохраняются в `localStorage`, поэтому изменения остаются после перезагрузки страницы в том же браузере и для того же источника сайта.
- **Адаптивный интерфейс.** CSS использует медиазапросы, чтобы перестраивать сетки и элементы формы под ширину экрана.

## Как устроено приложение

Состояние приложения хранится в объекте `state` в файле `js/app.js`. Функция `render()` обновляет интерфейс на основе текущего состояния и вызывает функции отображения карточек, результатов поиска и очереди модерации. Для работы с DOM используются `querySelector()`, `createElement()`, `append()` и `textContent`.

Для сохранения данных используются два ключа `localStorage`:

- `events` — опубликованные мероприятия;
- `pendingEvents` — мероприятия, ожидающие модерации.

Данные сериализуются через `JSON.stringify()` и восстанавливаются через `JSON.parse()`. Если сохранённого каталога ещё нет, приложение записывает в хранилище демонстрационный список. Сброс фильтров не удаляет сохранённые мероприятия.

> **Ограничения:** приложение работает на стороне браузера и не использует сервер или базу данных. Переключатель «А:вкл/А:выкл» — только демонстрация интерфейса модератора, а не настоящая авторизация или защита доступа. Данные хранятся локально в браузере и не синхронизируются между устройствами.

```text

├── styles/
│   └── main.css

│   └── images/
```

Пути в структуре важны: `index.html` подключает `styles/main.css` и `js/app.js`, а стили и JavaScript обращаются к изображениям в `assets/images/`.

## Как запустить

1. Скачайте или клонируйте репозиторий.
2. Убедитесь, что файлы находятся по путям, указанным в структуре проекта, а изображения присутствуют в `assets/images/`.
3. Откройте проект через локальный статический сервер, например расширение **Live Server** в Visual Studio Code. Можно открыть `index.html` напрямую, но для предсказуемой работы `localStorage` рекомендуется локальный сервер.
4. Откройте страницу в браузере. Установка зависимостей и сборка не требуются.

## Использованные технологии

- **HTML5** — семантическая структура страницы и формы.
- **CSS3** — оформление, CSS Grid для сеток карточек, Flexbox для расположения элементов, медиазапросы для адаптивности.
- **JavaScript (Vanilla JS)** — обработка событий, динамическое создание DOM-элементов, поиск, фильтрация, сортировка и управление состоянием.
- **Constraint Validation API** — проверка обязательных полей и ограничений длины.
- **Web Storage API (`localStorage`)** — сохранение каталога и очереди модерации между перезагрузками.
- **JSON** — сериализация и восстановление сохранённых данных.
- **SVG** — иконки в интерфейсе.

## Адаптивность

В CSS предусмотрены следующие режимы отображения:

- до 600px — карточки и очередь модерации располагаются в одну колонку, форма и шапка перестраиваются в столбик;
- от 601px до 900px — карточки располагаются в две колонки;
- от 901px — карточки располагаются в три колонки.

## Доступность и безопасность вывода

- Поля поиска и формы предложения имеют связанные подписи `label`.
- Для изображений демонстрационных мероприятий предусмотрены текстовые атрибуты `alt`.
- Текст, введённый пользователем, добавляется в DOM через `textContent`, а не вставляется как HTML-разметка.
- Для открытия и закрытия модального окна предложения предусмотрены кнопка закрытия, кнопка «Отмена», клик по подложке и клавиша `Escape`.
