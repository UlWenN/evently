---

## 1. Цель работы

Разработать статическую клиентскую часть веб-приложения с использованием HTML
и CSS: спроектировать структуру страницы, оформить её и обеспечить адаптивную
вёрстку коллекции однотипных объектов для дальнейшего развития в полноценное
клиент-серверное приложение.

---

## 2. Задание

1. Выбрать тему будущего приложения с коллекцией однотипных объектов.
2. Создать главную страницу с обязательными блоками: шапка с навигацией,
   главный заголовок, коллекция минимум из шести карточек, форма поиска,
   дополнительный информационный блок, подвал.
3. Использовать семантическую разметку HTML5.
4. Подключить внешний файл стилей и применить CSS Grid и Flexbox.
5. Обеспечить адаптивность страницы при ширине окна 360, 768 и 1280 пикселей.
6. Организовать файлы проекта согласно рекомендуемой структуре.
7. Подготовить `README.md` и загрузить проект в Git-репозиторий.

---

## 3. Описание проекта

**Название:** Evently

**Тема:** афиша городских мероприятий.

**Целевая аудитория:** жители города, которым нужно быстро найти интересный
досуг на вечер или выходные.

**Объект коллекции:** мероприятие (концерт, кинопоказ, выставка, лекция,
фестиваль, театральная постановка).

**Задача приложения:** помочь пользователю найти подходящее событие по месту,
типу и дате, не просматривая десятки разных сайтов.

## 5. Ход выполнения работы

### 5.1. Планирование структуры

На первом этапе определена тема проекта и составлена схема страницы. За основу
взят паттерн «каталог с фильтром»: сверху — навигация и поиск, в центре — сетка
карточек, снизу — пояснительная информация и подвал.

### 5.2. Разработка HTML-разметки

Документ оформлен как полноценный HTML5: указаны `<!doctype html>`, язык `ru`,
кодировка UTF-8, метатег viewport и осмысленный заголовок вкладки
«Афиша мероприятий». Внешний файл стилей подключён через `<link>`.

Использованы семантические элементы:

- `<header>` — шапка сайта;
- `<nav>` — блок навигации;
- `<main>` — основное содержимое;
- `<section>` — тематические секции (hero, поиск, мероприятия, о проекте);
- `<article>` — самостоятельные карточки мероприятий;
- `<footer>` — подвал.

Для каждого мероприятия подготовлена карточка, содержащая:

- изображение с осмысленным атрибутом `alt`;
- название (`<h3>`);
- дату, место и тип;
- краткое описание.

Форма поиска содержит три поля:

- `<input type="text">` — место;
- `<select>` — тип мероприятия;
- `<input type="date">` — дата.

Каждое поле имеет видимую подпись `<label>`, связанную через `for` и `id`,
а также атрибут `name` для дальнейшей работы с формой.

### 5.3. Оформление CSS

Стили вынесены в отдельный файл `styles/main.css`. Выбрана светлая
розово-фиолетовая палитра, основной шрифт — Arial. Реализованы:

- **CSS Grid** — для сетки карточек:
  ```css
  #events > div {
      display: grid;
      grid-template-columns: 1fr 1fr 1fr;
      gap: 30px;
  }
  ```
  Grid выбран потому, что он решает двумерную задачу — одновременное
  выравнивание карточек по строкам и столбцам.

- **Flexbox** — для шапки, навигации и формы:
  ```css
  header {
      display: flex;
      align-items: center;
      justify-content: space-between;
  }
  nav {
      display: flex;
      gap: 36px;
  }
  .search form {
      display: flex;
      gap: 36px;
  }
  ```
- Hover-эффекты на карточках и ссылках;
- Сохранена видимая рамка фокуса у ссылок, кнопок и полей ввода для
  пользователей, работающих с клавиатуры.

### 5.4. Адаптивная вёрстка

Добавлены медиазапросы:

- **до 600px** — карточки в одну колонку, форма и шапка в столбик;
- **601–900px** — карточки в две колонки;
- **от 901px** — карточки в три колонки.

Проверено в DevTools при ширине **360, 768 и 1280 пикселей**:
горизонтальная прокрутка не появляется, текст остаётся читаемым,
изображения не выходят за пределы карточек.

# Отчёт по лабораторной работе № 2

**Тема:** Интерактивный Frontend и State-Driven SPA  
**Проект:** Evently — афиша городских мероприятий  
**Выполнил(а):** Якорева Ульяна, группа ИВТ-ИСУ-302Б

## 1. Цель работы

Преобразовать статическую страницу проекта Evently, созданную в лабораторной работе № 1, в интерактивное одностраничное веб-приложение с использованием JavaScript. Реализовать работу с DOM и пользовательскими событиями, динамический поиск, фильтрацию и сортировку, проверку формы, делегирование событий, управление состоянием приложения и сохранение данных с помощью `localStorage`.

## 2. Задание

1. Организовать данные мероприятий в JavaScript и динамически отображать карточки на странице.
2. Реализовать поиск по тексту без учёта регистра.
3. Добавить фильтрацию по месту проведения, категории и дате, включая возможность сброса категории.
4. Реализовать сортировку мероприятий по дате в двух направлениях без изменения исходного массива.

7. Добавить удаление карточек с помощью делегирования событий.
8. Сохранять опубликованные мероприятия и предложения на модерацию в `localStorage`.

## 3. Описание проекта

**Название:** Evently.

**Тема:** афиша городских мероприятий.

**Основная сущность:** мероприятие, которое содержит название, дату, место проведения, город, категорию, описание и, для демонстрационных записей, изображение.

**Демонстрационные данные:** шесть мероприятий разных категорий — концерт, кинопоказ, выставка, лекция, фестиваль и театральная постановка.

**Принцип работы:** пользователь просматривает каталог, ищет события, применяет фильтры и сортировку либо отправляет предложение. Предложенные события сначала помещаются в очередь модерации и становятся частью основного каталога только после одобрения в демонстрационном режиме модератора.

Приложение работает полностью на стороне клиента. Серверная часть и база данных не используются; сохранение данных выполняется в браузере через `localStorage`.

## 4. Реализованный функционал

| № | Функциональность | Реализация |
|---|---|---|
| 1 | Динамический каталог | Карточки мероприятий создаются в JavaScript и добавляются в контейнер `.events-list`. |
| 2 | Поиск | Модальное окно поиска открывается по иконке. Результаты обновляются при событии `input`; поиск выполняется по названию, городу, месту, категории и описанию без учёта регистра. |
| 3 | Фильтрация | Основная форма фильтрует события по месту или городу, категории и точной дате. Значение «Все категории» отключает фильтр категории. |
| 4 | Сортировка | Список сортируется по дате по возрастанию или убыванию. Перед сортировкой создаётся копия массива с помощью `[...eventsFiltered]`. |
| 5 | Предложение мероприятия | Модальная форма собирает название, дату, место, город, категорию и описание, после чего добавляет запись в очередь модерации. |
| 6 | Валидация | Проверяются обязательность полей, минимальная длина названия в 3 символа и описания в 10 символов, а также максимальная длина описания в 500 символов. Сообщения об ошибках выводятся рядом с полями. |
| 7 | Удаление и модерация | Удаление опубликованных событий, одобрение и отклонение предложений доступны при включённом демонстрационном режиме модератора. Обработчики используют делегирование событий. |
| 8 | Сохранение данных | В `localStorage` хранятся ключи `events` и `pendingEvents`; для преобразования данных используются `JSON.stringify()` и `JSON.parse()`. |
| 9 | State-Driven UI | Состояние хранится в объекте `state`; после изменения данных или фильтров вызывается `render()`, который обновляет отображение каталога, результатов поиска и очереди модерации. |

## 5. Ход выполнения работы

### 5.1. Организация данных и состояния

В файле `js/app.js` создан массив `events` с шестью демонстрационными мероприятиями. Каждая запись содержит поля `name`, `date`, `location`, `city`, `category`, `description`, `image` и `imageAlt`.

Для управления приложением используется объект `state`. В нём хранятся текущий список мероприятий, строка поискового запроса, выбранное мероприятие, параметры фильтрации и сортировки, состояние режима модератора и список предложений, ожидающих рассмотрения.

### 5.2. Работа с DOM и динамическое отображение

Элементы страницы находятся с помощью `document.querySelector()`. Карточки и элементы результатов создаются через `document.createElement()`, заполняются текстом и добавляются в соответствующие контейнеры. Для вывода текстовых значений применяется `textContent`.

Функция `render()` обновляет подпись переключателя режима модератора, отображает или скрывает панель модерации и вызывает функции `renderEvents()`, `renderSearchResults()` и `renderPendingEvents()`. Таким образом, содержимое каталога формируется на основе актуального состояния, а не хранится в виде заранее прописанных карточек в HTML.

### 5.3. Поиск, фильтрация и сортировка

Для поиска используется отдельное модальное окно. При вводе текста обработчик события `input` сохраняет запрос в `state.searchQuery` в нижнем регистре и обновляет результаты. Поиск учитывает название, город, место проведения, категорию и описание. При выборе результата можно отобразить конкретное мероприятие либо применить фильтр по его категории.

Основная форма фильтрации считывает место, категорию и дату. Поиск по месту учитывает как название площадки, так и город. Пользователь может сбросить параметры формы кнопкой «Сбросить».

Сортировка поддерживает два направления по дате. Для сохранения исходного порядка массива перед вызовом `sort()` создаётся его копия. Если сортировка не выбрана, применяется исходный порядок элементов.

### 5.4. Модальное окно и проверка формы

Кнопка «Предложить мероприятие» открывает модальное окно с формой. Окно можно закрыть крестиком, кнопкой «Отмена», нажатием на подложку или клавиши `Escape`.

Поля формы имеют атрибуты `required`; для названия задан `minlength="3"`, а для описания — `minlength="10"` и `maxlength="500"`. Перед добавлением записи обработчик отправки отменяет стандартное поведение формы через `preventDefault()`, проверяет поля и использует свойства `input.validity` (`valueMissing`, `tooShort`, `tooLong`). Для невалидных полей выводятся понятные сообщения.

Если все поля прошли проверку, предложение добавляется в `state.pendingEvents` и сохраняется в `localStorage`. Оно не появляется в основном каталоге до одобрения модератором.

### 5.5. Делегирование событий и модерация

Удаление карточек реализовано через один обработчик события `click` на общем контейнере `.events-list`. Внутри обработчика применяется `e.target.closest(".delete-event")`, после чего определяется карточка и индекс мероприятия в исходном массиве. Удаление доступно только при включённом режиме модератора.

Для очереди предложений аналогичным образом используется делегирование на контейнере `.pending-events-list`. Кнопка «Одобрить» переносит запись из `pendingEvents` в основной список `items`, а кнопка «Отклонить» удаляет её из очереди. После изменения данных обновляется `localStorage` и повторно отображается интерфейс.

### 5.6. Сохранение данных

При запуске приложение проверяет наличие ключей `events` и `pendingEvents` в `localStorage`. Если опубликованный каталог ещё не сохранён, в хранилище записываются демонстрационные данные. В противном случае каталог восстанавливается из сохранённого JSON. Очередь модерации также восстанавливается при наличии сохранённых данных.

Добавление предложения, удаление мероприятия, одобрение и отклонение предложений сопровождаются сохранением изменённых списков. Поэтому изменения сохраняются после перезагрузки страницы в том же браузере и для того же источника сайта.

### 5.7. Оформление и адаптивность

Существующий файл `styles/main.css` сохранён. Для сеток мероприятий и очереди модерации применяется CSS Grid, а для расположения элементов шапки, формы и кнопок — Flexbox. Медиазапросы задают одну колонку на экранах шириной до 600px, две колонки в диапазоне 601–900px и три колонки на более широких экранах. Дополнительные стили оформляют модальные окна, результаты поиска, кнопки удаления и элементы модерации.
