# Отчёт по лабораторной работе № 1

**Тема:** Статическая клиентская часть веб-приложения
**Проект:** Evently — афиша городских мероприятий
**Выполнил(а):** Якорева Ульяна, группа ИВТ-ИСУ-302Б

---

## 1. Цель работы

Разработать статическую клиентскую часть веб-приложения с использованием HTML
и CSS: спроектировать структуру страницы, оформить её и обеспечить адаптивную
вёрстку коллекции однотипных объектов для дальнейшего развития в полноценное
клиент-серверное приложение.

---

## 2. Задание

1. Выбрать тему будущего приложения с коллекцией однотипных объектов.
2. Создать главную страницу с обязательными блоками: шапка с навигацией,
   главный заголовок, коллекция минимум из шести карточек, форма поиска,
   дополнительный информационный блок, подвал.
3. Использовать семантическую разметку HTML5.
4. Подключить внешний файл стилей и применить CSS Grid и Flexbox.
5. Обеспечить адаптивность страницы при ширине окна 360, 768 и 1280 пикселей.
6. Организовать файлы проекта согласно рекомендуемой структуре.
7. Подготовить `README.md` и загрузить проект в Git-репозиторий.

---

## 3. Описание проекта

**Название:** Evently

**Тема:** афиша городских мероприятий.

**Целевая аудитория:** жители города, которым нужно быстро найти интересный
досуг на вечер или выходные.

**Объект коллекции:** мероприятие (концерт, кинопоказ, выставка, лекция,
фестиваль, театральная постановка).

**Задача приложения:** помочь пользователю найти подходящее событие по месту,
типу и дате, не просматривая десятки разных сайтов.

---

## 4. Структура страницы

Страница состоит из следующих блоков:

| № | Блок | Назначение |
|---|---|---|
| 1 | `<header>` | Название проекта «Evently», навигация, иконка поиска |
| 2 | Hero-секция | Главный заголовок «Афиша мероприятий» и краткое описание |
| 3 | Форма поиска | Три поля (место, тип, дата) и кнопка «Найти» |
| 4 | Ближайшие мероприятия | Сетка из шести карточек с изображениями и характеристиками |
| 5 | «Как выбрать мероприятие?» | Подсказка по использованию фильтра |
| 6 | `<footer>` | Название проекта и информация о нём |

## 5. Ход выполнения работы

### 5.1. Планирование структуры

На первом этапе определена тема проекта и составлена схема страницы. За основу
взят паттерн «каталог с фильтром»: сверху — навигация и поиск, в центре — сетка
карточек, снизу — пояснительная информация и подвал.

### 5.2. Разработка HTML-разметки

Документ оформлен как полноценный HTML5: указаны `<!doctype html>`, язык `ru`,
кодировка UTF-8, метатег viewport и осмысленный заголовок вкладки
«Афиша мероприятий». Внешний файл стилей подключён через `<link>`.

Использованы семантические элементы:

- `<header>` — шапка сайта;
- `<nav>` — блок навигации;
- `<main>` — основное содержимое;
- `<section>` — тематические секции (hero, поиск, мероприятия, о проекте);
- `<article>` — самостоятельные карточки мероприятий;
- `<footer>` — подвал.

Для каждого мероприятия подготовлена карточка, содержащая:

- изображение с осмысленным атрибутом `alt`;
- название (`<h3>`);
- дату, место и тип;
- краткое описание.

Форма поиска содержит три поля:

- `<input type="text">` — место;
- `<select>` — тип мероприятия;
- `<input type="date">` — дата.

Каждое поле имеет видимую подпись `<label>`, связанную через `for` и `id`,
а также атрибут `name` для дальнейшей работы с формой.

### 5.3. Оформление CSS

Стили вынесены в отдельный файл `styles/main.css`. Выбрана светлая
розово-фиолетовая палитра, основной шрифт — Arial. Реализованы:

- **CSS Grid** — для сетки карточек:
  ```css
  #events > div {
      display: grid;
      grid-template-columns: 1fr 1fr 1fr;
      gap: 30px;
  }
  ```
  Grid выбран потому, что он решает двумерную задачу — одновременное
  выравнивание карточек по строкам и столбцам.

- **Flexbox** — для шапки, навигации и формы:
  ```css
  header {
      display: flex;
      align-items: center;
      justify-content: space-between;
  }
  nav {
      display: flex;
      gap: 36px;
  }
  .search form {
      display: flex;
      gap: 36px;
  }
  ```
- Hover-эффекты на карточках и ссылках;
- Сохранена видимая рамка фокуса у ссылок, кнопок и полей ввода для
  пользователей, работающих с клавиатуры.

### 5.4. Адаптивная вёрстка

Добавлены медиазапросы:

- **до 600px** — карточки в одну колонку, форма и шапка в столбик;
- **601–900px** — карточки в две колонки;
- **от 901px** — карточки в три колонки.

Проверено в DevTools при ширине **360, 768 и 1280 пикселей**:
горизонтальная прокрутка не появляется, текст остаётся читаемым,
изображения не выходят за пределы карточек.
